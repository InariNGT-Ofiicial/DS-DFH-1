# PORTING：与原稿的差异台账

本片是从参考项目 [`MisakaZentai/world-execute-me-dsh-pv`](https://github.com/MisakaZentai/world-execute-me-dsh-pv)
**同构移植**来的。移植的是**纪律**不是代码：三个不变量照搬，内容层整个换掉。

这份文件逐条列出「哪些没变、哪些换了、哪些没核实」。**未核实项也写在这里**——
一支片子说不清哪里不确定，等于没说清哪里确定。

## 一、照搬的不变量（改任一处都会连带改掉别的）

| 不变量 | 说明 |
|---|---|
| **帧 = 歌曲时间 t 的纯函数** | 无剪辑软件、无手工关键帧、无时间轴拖影。红利：可逐像素验证、可任意分块并行 |
| **固定五层合成序** | 场景 → 跨切物件 → 主体 → chrome（每帧重画、永不参与变换）→ 后期 |
| **分镜三表 + lint + 弧线** | `SHOTS` / `CHOREO` / `check_variety()` / `check_clock()` / `ui_gain(t)` / `glow_arc(t)` |

### 主体为什么是程序化绘制

原稿的鲸鱼少女是第三方立绘（CC BY-NC-SA 4.0，署名链见其 NOTICE）。
移植时有两个选择：沿用那套素材，或者重画一个主体。

选了后者，理由有两条：**授权上更干净**（本片零第三方图像素材），
**工程上更合适**——东方红一号是个**球体 + 四根天线**的 72 面体，天然适合用几何原语画；
而且它在片中自转 **120 r/min = 2 r/s**，在 24 fps 下**每帧正好转过 30°，即 12 个相位**，
所以只要缓存 12 张相位图，既忠实又让渲染保持在纯函数的可控成本内（源码里有 `assert` 守住这个关系）。

**代价照实说**：外观是**示意性**的，不是照片级复原。片头那格特意标了这一点。

## 三、时钟：换歌第一件事是重新标定，不许猜 BPM

原稿的教训是「不许先跑起来看看」。本片照做，而且遇到了一个典型陷阱：

1. 谱流 → onset 包络，自相关给出最强候选 **110.0 BPM**（附点）与 **73.34**（其 2/3）。
2. 钢琴曲的自相关容易出**倍频歧义**，所以换一个更硬的锚：**歌词句间隔**。
   实测句距中位数 **3.3300 s**，稳定得惊人。
3. 令「一句 = 4 拍」→ **BPM = 60 / (3.3300/4) = 72.072**。
4. **反向验证**：按该网格给 onset 包络打分，`72.07 → +0.07450`、`36.04 → +0.07566`、
   `144.14 → +0.07424`。前三个是同一网格的 1×/½×/2×，**得分几乎相同**——
   这正是「网格选对了」的指纹；若选错，倍频之间会明显拉开。

每个镜头的边界都钉在**唱词起点**上——那些时间是人标的，比网格可信。

## 四、本机相关的实现选择（非本机可能不同）

| 项 | 本片做法 | 为什么 | 换台机器要注意 |
|---|---|---|---|
| **分片编码器** | `utvideo`（无损 RGB） | libx264 多进程编码 **OOM**（可用内存只剩 2.0/16.8 GB 时 `malloc failed`）。utvideo 内存占用极小 | 内存充裕可以换回 libx264rgb |
| **并发数** | 3–4，**按内存定不按核数** | 24 核默认给到 22 worker → 44 进程 → `MemoryError` | 这是最容易踩的坑，见 DEVLOG |
| **中间帧** | **不落 PNG，流式喂进各自 ffmpeg** | 7922 张小 PNG 只有 ~1.1 MB/s（实时扫描拖累），**并行比串行还慢**。改流式后全片 293.8 s | 换成 SSD 可以再测 |
| **文件名替换** | `seg.unlink()` + `shutil.move` | 某些环境下 `Path.replace()` 恒拒访 | 常规系统可以直接 `replace()` |
| **后期无拖影** | `trail=0` | 拖影破坏纯函数与分块并行。拿一点观感换全程可复算 | 这是设计决定，不建议改 |

## 六、未核实项（必须写明的边界）

- ⚠️ **`el_her` 的状态读数不是遥测实录。** 电压 / 温度 / 调谐三条读数是**艺术化演出**
  （有界随机），不是真实遥测。**只有 `spin 120 r/min` 是事实。**
- ⚠️ **音画对齐只做到镜头边界对齐唱词起音**，**未做逐字对齐的嘴型 / 波形级验收**。这一项**未核实**。
- ⚠️ **气动数值出自假定弹道。** 东方红一号上升段没有公开气动数据；
  `max-Q ≈ 18.9 kPa`、`滞止温度 12 °C` 来自 `C_D=0.30` / `Isp=260 s` 的假定弹道。
- ⚠️ **2026 年轨道根数是外推不是实测。** 记录止于 2009 年重测（430 / 2075 km），
  之后按阻力模型外推。片中用 `[推定]` 标注。
- ⚠️ **事实口径存在分歧。** 英文维基给 441 / 2286 km、68.42°、114.09 min；
  中文官方与 CAST 参数表给 439 / 2384 km、68.5°、114 min。本片采用**中文官方口径**，
  并在镜头里只上屏后一组数字。这是**已知分歧**，不是错误。
- ⚠️ **以上比对均为抽点验证**（定稿 22 点），**不表示每一帧都满足同样指标**。

## 七、继承来的调色板

沿用原稿的 `amber` 荧光屏调色板，未新增调色板。
`ME`（蓝）是本片**保留但未使用**的第二声部——本片只有一个主体，用 UI 琥珀画她。

一处本片才发现的结构性问题：**这套调色板最亮色 `(255,176,0)` 亮度上限只有 143.7，
而后期只减不加**，所以全片**结构性没有高光**（原稿 0.51% vs 本片旧版 0.00%）。
本片的解法是一个**白热层** `tk.hot(level)`，把顶层琥珀推近白 `(247,247,247)`——
**每帧只准一个元素用**。这条纪律是后加的，见 [DEVLOG.md](DEVLOG.md)。
