# MAKING_BLOCKS：用色块画事件

这支片子里**没有一张外部图片**。卫星、火箭、钱学森、专列、发射台、报纸照片——
全部是字符网格上的色块，由代码当场画出来。

这份文档讲**怎么再画一个**。不是讲美学，是讲机制、网格、零件库和验收。
代码在 [`pv/bigscene.py`](../pv/bigscene.py)（大场景）与 [`pv/icons.py`](../pv/icons.py)（小图标）。

---

## 0. 为什么不画矢量，也不引照片

三条理由，按重要性排：

1. **版权**。参考项目的角色立绘是 CC BY-NC-SA，不可商用。本片主体若也依赖外部图，
   就继承了同一份限制。改成程序化绘制后，仓库里**零第三方图像素材**。
2. **纹理一致**。全片是 CRT 半块字符质感。贴一张照片进去，无论怎么调色，
   **像素的“颗粒”不是同一套**，会立刻显得是外来的。
3. **纯函数**。色块 = 字符网格 = 一个确定性的字符串。同一组参数永远出同一张图，
   可以 `lru_cache`，可以复算，可以逐像素验证。

> 一句话：**这是终端给得起的分辨率，就按终端的方式画。**

## 1. 两级尺度

片子里有两套画法，共用同一套字符语义，但尺寸和目标不同。

| | 小图标 `icons.py` | 大场景 `bigscene.py` |
|---|---|---|
| 网格 | 约 **21–24 × 8–10** | 固定 **44 × 30** |
| 默认 cell | 4 px | `fit_cell()` 自适应，上限 14–16 |
| 数量 | **40 个**（`CRAFT` 9 + `STORY` 25 + `PARTS` 6） | **24 个**（`BUILDERS`） |
| 用途 | 给一行日志做注脚 | 占满画面另一半，给「这一格讲的是谁」 |
| 出现位置 | 文本行左侧、列表行内 | `el_scene` / `el_paper` 的配图区 |

小图标是**注脚**，大场景是**主体**。同一条事件通常两个都有，
并通过 `BIG` 表绑在一起（见 §4），保证两栏说的永远是同一件事。

## 2. 字符即灰度

两种尺度用同一张表（两边各有一份，值完全一致）：

```python
LEVELS = {"#": 1.00, "+": 0.62, "-": 0.34, ",": 0.22, ".": 0.15, " ": 0.0}
```

渲染时每个字符变成**一个实心方块**，亮度取上表的值。于是：

- `#` 是实心亮块 —— 主体轮廓、该被看见的东西
- `+` 是次亮 —— 体积、衣料、机身
- `-` 是暗 —— 边缘、结构线、次要物件
- `,` / `.` 是极暗 —— 空气、远景、氛围
- 空格是透明

**关键约束：只有 6 档。** 不要试图用更多字符（`*`、`@`、`%`）——
渲染器不认，`LEVELS.get(ch, 0.0)` 会静默返回 0，**画不出来也不报错**。
这是最容易踩的坑：你写了一屏 `@`，结果一片空白，而构建是绿的。

## 3. `Sheet`：44×30 的画布

```python
class Sheet:
    def __init__(self, w=44, h=30, bg=" ")
    def px(self, x, y, ch)
    def rect(self, x, y, w, h, ch="#", fill=True)
    def disc(self, cx, cy, rx, ry, ch="#", fill=True, ring=0.72)
    def line(self, x0, y0, x1, y1, ch="#")
    def tri(self, a, b, c, ch="#")      # 扫描线填充
    def stamp(self, rows, x, y)          # 贴一段现成的字符块
    def rows(self) -> list[str]
```

全部返回 `self`，可以链式写：

```python
s.rect(3, 24, 12, 5, "+", fill=True).line(0, 29, 44, 29, ".")
```

**坐标系**：`x` 向右 0–43，`y` 向下 0–29。**没有负坐标，越界静默丢弃**（`px` 里那个 `if 0 <= x < w`）。
所以一个画歪的场景不会抛异常，只会安静地少一块——这也是要目视预览的原因。

**`disc` 的 `ring` 参数**：`fill=False` 时只画环，`ring=0.72` 是内边界。
`ring` 越小环越厚。天文台天线那种「盘面 + 外圈」就是两次 `disc`：

```python
s.disc(9, 15, 7, 4.34, "+")              # 实心面
s.disc(9, 15, 7, 4.34, "#", fill=False, ring=0.55)   # 边缘圈
```

## 4. 零件库：不要每次从头画人

`bigscene.py` 提供 7 个零件，**这是画面统一感的来源**：

| 零件 | 签名 | 画什么 |
|---|---|---|
| `head` | `(s, cx, cy, rx, ry, face, hair, eta)` | 头：脸 + 发盖 + 耳朵，约 14 格宽可读 |
| `glasses` | `(s, cx, cy, half, ch)` | 眼镜——**让一个色块脸变成某个人最有效的单一线索** |
| `shoulders` | `(s, cx, y, half, depth, suit, shirt)` | 西装 + 领口 V + 领带 |
| `rocket` | `(s, cx, top, bot, half, body, edge, fins, noz)` | 箭体：锥 + 筒 + 尾翼 + 喷管 |
| `dish` | `(s, cx, cy, r, face, back, stem)` | 抛物面天线 + 基座 |
| `figure` | `(s, cx, top, h, head_r, ch, arm)` | 站立的人：头、躯干、两腿，可选举手 |
| `flag` | `(s, x, y, w, h, pole, ch, pole_ch)` | 旗杆 + 三角旗 |

组合示例——`_qian`（钱学森，581 会议 / 1968 院长），**原文照抄**：

```python
def _qian(s: Sheet):
    """1958-08 / 1968-02: the portrait. Short hair, high forehead, glasses, suit and tie."""
    head(s, 22, 12, 9, 11, face="#", hair="+")
    glasses(s, 22, 11, half=2)
    # nose and mouth, kept to the centre line so the face does not smear
    s.line(22, 13, 22, 17, ".")
    s.px(21, 17, ".")
    s.rect(19, 19, 7, 1, ".")
    shoulders(s, 22, 24, half=15, depth=6, suit="+", shirt="#")
    s.tri((20, 27), (25, 27), (22, 30), ".")
    return s
```

注意几个真实的选择，不是随便写的：

- `head(..., rx=9, ry=11)` 是**从 §7 的“人形不要画大”反推的**：整个 Sheet 只有 30 行高，
  头占 22 行高的椭圆，肩膀压在 `y=24`，画完正好触底。
- 五官只用 `.`（0.15），**不用 `#`**——脸是主体，但不能比轮廓线更亮，否则整张脸变成一块白。
- 鼻子和嘴**压在中心线 `x=22`** 上。代码注释写了原因：`kept to the centre line so the face
  does not smear`。偏一格，脸就歪。

> **纪律：先找零件，找不到才自己画。** 自己画的那部分要能说清「为什么零件不够用」。
> 否则片子会渐渐长出十几种互不相容的人形。

## 5. 新增一个场景：四步

以「1970-04-01 专列抵达酒泉」为例。

### ① 写一个 `_xxx(s)` 函数

只接收 `Sheet`，把自己画上去，返回 `s`。函数名前面下划线，docstring 写**这一格在物理上发生了什么**
（不是「画一列火车」，而是「专列，以及它运的东西」）。**原文照抄**：

```python
def _train(s: Sheet):
    """1970-04-01: the special train, and the vehicle it was carrying."""
    s.rect(2, 18, 12, 7, "+", fill=True)          # 平板车
    s.rect(2, 12, 8, 6, "+", fill=True)           # 车厢
    s.rect(2, 12, 8, 6, "#", fill=False)          # 车厢轮廓
    s.rect(4, 9, 4, 3, "#", fill=True)            # 烟囱
    for k in range(3):
        s.disc(4 + k * 4, 26, 2, 2, "#")          # 车轮
    s.rect(15, 18, 27, 3, "+", fill=True)         # 后挂的平板
    rocket(s, 28, 8, 18, half=3, body="+", edge="#", fins=False, noz=False)   # 箭体
    for k in range(4):
        s.disc(19 + k * 6, 26, 2, 2, "#")         # 车轮
    s.line(0, 28, 44, 28, ".")                    # 地面
    s.line(5, 4, 39, 4, "-")                      # 远处的高架
    return s
```

三个可复用的手法：

- **`fins=False, noz=False`** —— 专列上的箭是**躺着的、没装尾翼和喷管的**。
  同一个 `rocket()` 零件，去掉两个开关就是另一个状态。**零件要能拨，不要另写一个。**
- **车轮用 `disc(..., r=2)` 而不是 `px`** —— 在 44×30 里，2 格直径是“圆”的最小可读尺寸。
  1 格是点，3 格开始占地方。
- **地面用 `.`、高架用 `-`** —— 靠亮度分前后景，不靠位置。这是全片统一的**景深语法**。

### ② 注册到 `BUILDERS`

```python
BUILDERS = {
    ...
    "train": _train,
}
```

键名 = 场景名，短、小写、无语义修饰。

### ③ （可选）挂到 `BIG`

`BIG` 把**日志行的 key** 映射到**场景名**。key 来自 `icons.py` 的小图标名：

```python
BIG = {
    "train": "train",     # 1970-04-01  专列抵达酒泉
    ...
}
```

为什么要这张表、而不是在分镜里直接写场景名？
因为一行日志可以换小图标而不换画面。**表在这里，改 key 的人不必记得同时改画面。**

`key_of()` 负责解析：已经是场景名就直接通过，否则查 `BIG`，查不到回落到 `"station"`。

### ④ 在分镜里用

```python
("scene", dict(lines=PTRAIN_STORY, title="702 / 经酒泉"), (832, 56, 1164, 604))
```

或者给报纸配照片：

```python
("paper", dict(headline=F.PAPER_HEADLINE, photo="liftoff"))
```

`el_scene` 与 `el_paper` 都会走 `bs.key_of(key)` → `fit_cell()` → `draw()`。

## 6. 渲染链：字符到像素

`bigscene` 这一侧：

```python
rows(name)    -> tuple[str, ...]        # 缓存的字符网格
sprite(name, cell, tint)                # 字符 -> RGBA 图，lru_cache(64)
fit_cell(name, max_w, max_h, cap=16)    # 算出能装下的最大 cell
draw(c, name, box, cell, tint, alpha)   # 居中贴进 box
```

`icons` 这一侧签名略有不同（`draw(c, xy, name, ...)`，按左上角贴，或给 `x0/x1/y0/y1` 居中）。

**`sprite()` 内部做了四件事**：

1. 每个字符按 `LEVELS` 写成灰度像素 → 得到一张 `cols×rows` 的 `L` 图；
2. `resize(NEAREST)` 到 `cell` 倍——**必须 NEAREST**，双线性会把色块糊成雾；
3. `cell >= 3` 时叠加**一像素沟槽**，让每个方块看起来是一格终端字符（不是一大坨）；
4. 上色 + 由亮度生成 alpha（`<8` 判为全透明，其余 `×1.25` 提亮）。

> **为什么 `cell < 3` 就关掉沟槽**：2 px 的格子里再挖 1 px 沟槽，方块就只剩一条线，
> 整体会变灰。小尺寸下要的是**墨量**，不是格子感。

## 7. 验收：怎么知道自己画对了

色块画**不会报错**，所以验收必须靠工具和眼睛。

| 手段 | 命令 / 做法 | 抓什么 |
|---|---|---|
| 字符预览 | `python -c "import bigscene as bs; print('\n'.join(bs.rows('train')))"` | 形状对不对，一格一格看 |
| 尺寸溢出 | `fit_cell` 保证不超框；`draw` 里还有一层 `crop` 兜底 | 贴出去被切掉一角 |
| 接触表 | `python contact_sheet.py` | 全片视觉索引，看占比与位置 |
| 同帧 A/B | `python ../tools/ab_loci.py` | 换成新场景后墨量、峰值变了多少 |
| 字符审计 | `python ../tools/tofu_audit.py` | 只对文字有效，色块不涉及 |

**尺寸约束（硬）**：网格是 `44×30`，`Sheet(w,h)` 默认就是它。
`_xxx()` 里写超过 43 或 29 的坐标**不会报错，只会丢像素**。
画完先跑一遍字符预览，用等宽字体看——**这是最便宜的一关**。

## 8. 踩过的坑

- **写了 `LEVELS` 不认的字符**（`@` `*` `%`）→ 静默变透明。只能用 `# + - , . ` 和空格。
- **`lru_cache` 让改动看不见。** `rows()` 是 `lru_cache(None)`、`sprite()` 是 `lru_cache(64)`。
  在 REPL 里改了函数不重启进程，看到的永远是旧图。**改完重启，或手动 `cache_clear()`。**
- **越界静默丢弃**，导致「少一块」而非报错。画完必须目视。
- **`cell < 3` 没有沟槽**，看起来会比预期亮/糊——这是有意的，别当成 bug 去修。
- **人形画得越大越不像。** 44×30 里一个人约 10–14 格高，`head_r=4`。
  再大就开始暴露“这不是肖像”，反而更差。**承认这是图示，不是复原。**

## 9. 这套画法适合什么、不适合什么

**适合**：有明确轮廓的物件（卫星、火箭、天线、车）、有单一姿态的人（站、举旗、挥手）、
场景的**骨架**（站台、厂房、控制台）。

**不适合**：面孔表情、透视、连续动作、任何需要“像照片”的东西。
它们在这个分辨率下只会变成噪点，而且会破坏全片的统一质感。

> 判断标准很简单：**你能用一句话说清这一格在物理上发生了什么吗？**
> 说不清，就不是画法问题，是分镜还没设计完。
