## 一、一句话概括

这是一支**用代码逐帧渲染**的 PV：没有剪辑软件，没有手工关键帧，没有视频素材。

> 「每一帧都是歌曲时间 t 的纯函数：24 fps，画布 1280×720。」——`docs/HOW_IT_WORKS.md` 第一句

画面被劈成左右两半，各自一套完全不同的技术栈，最后在**内存里**缝在一起：

| | 左：她和你的聊天窗口 | 右：她所在的"世界" |
|---|---|---|
| 世界里的什么 | DeepSeek Harness（dsh）的网页前端 | TUI 风格的模型可视化引擎 |
| 怎么画 | 用 dsh 自己的 CSS 类名拼 HTML → 无头 Chromium 截图 | PIL **逐字符**画（Transformer、卷积、扩散采样、注意力、KV cache、RLHF…） |
| 谁画的 | `batch_a1.py` … `batch_g.py`、`seg_page.py` + `seg_shot.mjs` | `tuikit.py` + `full/sec_*.py` + `continuity_full_v2/s_*.py` |
| 缝合处 | `dsh_her.py`（内存里替换函数，不改生产文件） | 同左 |

**没有 dsh 进程，没有服务器，不调用任何模型。** 左边那个"聊天窗口"自始至终只是一堆静态 HTML 截图。

## 二、工作流逆向：五段式流水线

`build.py` 是唯一入口，五步串行，每一步也能单独跑：

```
npm install && npx playwright install chromium
# 把歌曲放成 input/song.mp3
python build.py all          # check → lyrics → dancer → pages → render
```

### ① check —— 开跑前的把关

- 查 `ffmpeg` / `ffprobe` / `node` 在不在 PATH
- 查 `node_modules/playwright` 有没有装
- 查 4 个字体：`consola.ttf`、`consolab.ttf`、`msyh.ttc`、`seguisym.ttf`（可用环境变量 `PV_F_MONO`/`PV_F_CJK`/… 换）
- 查 `input/song.mp3` 的 **sha256** 是否等于 `79c4e53663c7966b7160bff19326e614658485d4ce0199ff82715ea9d0a418fc`

最后一条很妙：**不匹配也不报错退出**，只提示"能渲染，但如果你的副本有偏移，唱词和镜头会整体漂移"。因为整支片子是按"**解码后第一个采样为时间零点**"逐帧对齐的——歌不一样，整条时间线就错位。

### ② lyrics —— 用 sha256 把「歌词」和「时间」拆开

这是整份工程里最讲究的一步，也是最能看出作者法律意识的地方。

版权上：**歌词原文不能进仓库**。但片子又完全挂在歌词结构上（切镜时间、每一处 `lyric_start()` 查询都靠它）。

作者的解法：

1. 仓库只存 `data/timing/` 两份**不含文字**的数据——每个时间、每个标志、每行的 **sha256**、每个词在行内的字符区间；
2. `tools/lyrics.py fetch` 从 LRCLIB（条目 36914646）把你的歌词下到**你自己机器**上；
3. `merge` 把文字填回去，**逐行比对 sha256**；只要有一行对不上就**什么都不写**，并列出对不上的行。

重建出来的文件必须和当年出片用的**逐字节一致**（连换行符、缩进、结尾是否补换行都在数据里记着）：

```python
for name, data, expected in [(lrc["target"], lrc_bytes, lrc["sha256"]), ...]:
    if got != expected:
        sys.exit(f"{name}: every line matched but the rebuilt file does not ...; nothing was written.")
```

> 备注里还留着一处对词条本身错误的修正：`FIXES = {"Trios": "Trois"}`——「LRC 自己的错字」。

### ③ dancer —— 替身舞者

右边有很多画面是拿**舞者的帧**做的：点云、样本格、特征图、热图、字形人。

原片那些帧来自第三方 MMD 模型和动作（YYB 伯爵女仆模型 + 两支舞）经视频生成模型产出。作者明确写了：

> **OPEN QUESTION**：这些现存说明没有明确覆盖 AI 推理参考及其衍生视频……本项目未取得可证明覆盖此用途的补充授权。

于是仓库**不分发这些帧**，改由 `tools/placeholder_h3.py` 用鲸鱼娘立绘生成**同名、同帧数、同文件名**的替身：「她站着，随节拍轻轻摇摆」。

替身怎么动：

- 一小节（4 拍）渲染成 **44 帧的循环**，每个 take 的每一帧按自己在歌里的位置取对应相位
- 节拍网格：`FIRST_BEAT = 0.1807`，`BEAT = 60/130`（BPM 130）
- 摆动 8 px（头部左右），每拍下沉 1.4% 身高
- 帧规格：45 行 × 70 字符的字形网格 + 420×540 RGBA 图；**轨迹用原片自己的追踪器算**（`grok_rig.py`：feet / matte / trace，往白底上合成后每 6×12 px 一个字形格）

**替身不是"凑数"，是格式完全兼容**——所以右边引擎一行代码都不用改。而且：如果你自己有舞蹈帧，按同格式丢进 `pv_cache/`，工具看到文件在就跳过。

### ④ pages —— 每帧一张 HTML，然后截图

这是左边那半边的全部真相：

```python
frames = [{"n": n, "t": round(n / FPS, 4), "body": body(n / FPS), "sheets": STYLED, "measure": False}
          for n in range(round(T0 * FPS), round(T1 * FPS))]
```

`body(t)` 是一个**把歌曲时间映射成 HTML 字符串**的纯函数。每帧写进 json，交给 `seg_shot.mjs`：

```javascript
const page = await browser.newPage({ viewport: { width: 354, height: 537 }, deviceScaleFactor: 1 });
for (const f of frames) {
  await page.evaluate(({body, t, sheets, ids}) => {
    for (const id of ids) document.getElementById(id).disabled = !sheets.includes(id);
    const app = document.getElementById("app");
    if (app.dataset.body !== body) { app.innerHTML = body; app.dataset.body = body; }
    for (const a of document.getAnimations()) {          // ★ CSS 动画钉在歌曲时间上
      a.pause();
      const d = a.effect?.getTiming().duration;
      a.currentTime = typeof d === "number" && d > 0 ? (t * 1000) % d : 0;
    }
  }, {...f, ids: SHEETS});
  await page.screenshot({ path: `dsh_frames/${String(f.n).padStart(5,"0")}.png` });
}
```

两个关键点：

1. **`app.dataset.body !== body` 才重设 DOM** —— 连续帧 body 没变就直接复用，省掉反复重排的开销；
2. **动画不是"播放"的，是"求值"的** —— 把每个动画 `currentTime` 直接设成 `t*1000 % duration`。所以那一行"思考中…"的扫光、光标闪烁，**每一帧都是确定的**，跑两遍得到同一张图。

界面从哪来？`extract_css.py` 从 `film/vendor/` 下 **7 个 dsh 的 client-ui 包**（theme / chat / tool / conversation / message-feedback / deliverables / layout）的 `client.js` 里正则抽出 CSS 字符串，再拼成 `dsh_components.css`（103 KB）；连混淆后的类名映射（`disclosure_map.json`）都是从 minified bundle 里反解出来的。

也就是说：**这个窗口是用 dsh 自己的皮肤渲染的 dsh**——不是截图、不是仿画。

### ⑤ render —— PIL 逐帧 → ffmpeg

```python
# 无损母版：libx264rgb, qp 0, rgb24
run([python, "dsh_her.py", "render", "0", str(END), "film_master.mp4", str(a.workers)], cwd=DSH, env=e)
# 混入结尾提示音（207.873 s）→ BT.709 转码
audio = ["-i", SONG, "-i", DSH/"chime_g.wav", "-filter_complex",
         "[1:a]atrim=0:{END},asetpts=PTS-STARTPTS[s];[2:a]adelay={CHIME_MS}|{CHIME_MS}[c];[s][c]amix=inputs=2:duration=first:normalize=0[a]", ...]
tags = ["-colorspace","bt709","-color_primaries","bt709","-color_trc","bt709","-color_range","tv"]
```

- 按 CPU 核数**分段并发出**无损 720p 母版，再 concat
- 交付版 CRF 16 / preset slow / BT.709 / yuv420p
- `--4k` 的 3840×2160 是母版**逐像素放大 3 倍**（`flags=neighbor`）——因为 720p 是像素画，放大必须整块
- `--gpu` 可把辉光、残影、扫描线挪到 torch+CUDA 上

## 三、四个真正值得偷的设计

### 1. 「帧 = t 的纯函数」不是口号，是可验证的

没有时间轴对象、没有上一帧状态、没有随机种子逃逸。`v2.frame(n)` 只吃一个整数帧号。

> **实测（本机跑通）**：直接 import 仓库的 `batch_a1`，
> `body(20.0) == body(20.0)` → `True`（逐字相同，4187 字符）；
> `body(20.0) != body(21.0)` → `True`。
> 输出片段里带着 `avatars/a1_noise12.png`（随机初始化的噪声头像）和 `运行中 · ckpt-009968`。

好处：**任何一帧都可以单独出图调试**（`dsh_her.py stills 6 9 14 104 109 112.3`），断点续跑不用管状态。

### 2. 用「运行时的内存替换」代替改源码

这是全篇最漂亮的一手。右边的引擎本来会画一个"她"的字形窗格；现在要把那个窗格换成 dsh 截图，但**不能改动右边任何生产文件**。

`dsh_her.py` 的做法是 `install()` 里替换函数：

```python
orig_layer = kit.her_layer
def her_layer(t, call, box_level=1.0):
    if not inside(t):  return orig_layer(t, call, box_level)
    ...
    im = dsh_frame(t)                         # 取这一帧的截图
    layer.alpha_composite(win, (x0, y0))
kit.her_layer = her_layer
```

于是**右边镜头对"她"做的推拉、隔离、滑出，全部原样作用在这个窗口上**——因为它换的只是"这个图层画什么"，不是"这个图层怎么动"。

同一个技巧串成一整套：

- `tk.vignette` → 换成空图（窗口和歌词已经够抓眼，不需要暗角）
- `tk.box` → 标题 `/dev/me` 改成 `dsh web`
- `engine.header` → 合成心跳换成**歌曲的实时波形**（`dsh_wave.py`，2.4 秒窗口、1 ms RMS 缓存 `wave_rms_1ms.npy`）
- `engine.lyric_tokens` / `stage.lyric_now` → 换成逐词跟唱（`words.py`）
- 分组补丁链 `dsh_patch_{fix,r1,d,mem,e,f,g}.py` 依次 `install()`，各自登记自己的 `COVER` / `LEAD` 时段

还有一张 `COVER` 表（哪些时段由窗口接管）和一张 `LEAD` 表（这一刻谁是主角，另一边亮度降到 42%）——**导演调度也是数据**。

### 3. 音频驱动一切

`full/music.py` 把歌算成 **48 Hz × 5 类特征**：`loud`（总 RMS）、7 个频带（40 Hz–10 kHz）、`kick`（低频起音）、`flux`（全频带起音）、`cent`（能量重心，判"音在高处还是低处"）。

然后映射到她的像素画像上：

> - `body = spectrum` 每一行格子按它高度对应的频带移动（头发=高频、裙摆和尾巴=低频），像一道波从她身上跑过
> - `kick` 整张画像在鼓点上**涨一圈、跳一格**
> - `flux` 起音处几个格子闪到最亮
> - `loud` 安静段落有格子掉出去，歌一涨她又填回来

外加两套时钟：`engine.pulse(t)`（节拍脉冲，`exp(-(t - 本拍时刻)/0.14)`）和逐词对齐的 `words.py`（**左边每一个呼应动作都落在对应唱词的起音上**，`sung_words.w(line, i)` 直接查词的时间）。

### 4. 版权合规被做成了工程

不是"附个 LICENSE"就完事，是**写进流水线**：

### 验证三：**这个仓库不能开箱即跑**（实测结论）

按 README 步骤尝试 import 页面脚本，撞到两道墙：

```
FileNotFoundError: film/world_execute_word_timing_20260927/word_timeline.json   ← 歌词时间轴（构建期产物）
StopIteration: sung_words.py:16 `next(x["start"] for x in WORDS if ...)`        ← seg_page.py 在【模块级】就要真实词级时间
```

`seg_page.py` 第 358 行 `STEPS = [w(49,0), w(49,3), w(51,0), w(51,3)]` 是**模块级**求值——也就是说，**没有自备歌词，连"生成一帧 HTML"都做不到**，更别说渲染。

本次绕过办法：拿仓库自带的 `data/timing/word_timeline_notext.json` 骨架（98 行 / 395 词的 onset，只是没文字）拼出一个时间轴，纯函数就能跑了。但要走完整流程，仍然必须自己准备 `song.mp3` + 从 LRCLIB 取歌词。

> 这不是缺陷，是**版权设计的必然结果**：越干净地把版权内容剥离，开箱可跑性就越低。作者选了前者，并且在 README 里把代价写清楚了。

### 验证四：拿本机的真 DSH 对照（这一步最硬）

本机确实装着它的"参照物"。DSH 是一个 Electron 桌面应用：

| 项 | 值 |
|---|---|
| 安装位置 | `D:\DSH\DeepSeek Harness.exe`（244 MB，Electron 壳） |
| 应用 | `@deepseek-ai/dsh-desktop` **0.2.0-rc.1** |
| 内置 runtime | `@deepseek-ai/dsh-desktop-runtime` 0.2.0-rc.1，含 `dsh` / `dsh-agent` / `dsh-acp` / `dsh-api-gateway` 等整套 |
| 插件框架 | `@deepseek-ai/cordis` 4.0.4 —— 正是仓库 vendor 里 `dsh-client-ui-cordis` 那套 |
| 数据目录 | `~/.dsh/`（profiles / sessions / skills / storages） |
| 安装时间 | 2026-09-28（**正好是视频发布那天**） |

前端资源封在 `resources/app.asar`（118 MB，**13026 个条目**）。解析 asar 后挖出 **629 个 `@deepseek-ai` 包**，其中就有 `dsh-web-frontend/dist/assets/` 和 40 多个 `dsh-client-ui-*`。

|---|---|---|---|
| `dsh-web-frontend/dist/assets/vendor-BNsW4eBh.css` | 29288 | 29288 | **逐字节相同**（`9860041e810431da…`） |
| `dsh-web-frontend/dist/assets/index-*.css` | `index-DPX2bQLO.css` 51949 | `index-Cq6ljTv2.css` 75665 | 同名不同物 |

| `dsh-client-ui-cordis/lib/client.js` | 74479 | 75413 | 不同 |

**类名检索**（在本机 115 个前端文件 / 14.6 MB 里搜）：

| 检索项 | 命中 |
|---|---|
| `dsw-alias-bg-base` / `dsw-font-family` / `data-ds-dark-theme`（设计 token） | 45 / 78 / 23 ✅ |
| 仓库 `dsh_components.css` 抽出的 **347 个组件类名** | **0 / 347** |
| `Sixlwa_userRow`、`uV2eYG_card`、`lcKema_summary` 等 10 个 PV 主用类名 | **0 / 10** |

- **稳定的是设计体系**：`dsw-alias-*` 那套 token、以及 vendor chunk（第三方依赖 CSS）跨版本逐字节不变；
- **变的是应用层**：CSS-modules 的哈希前缀、图标符号名随每次构建重算，所以全部对不上；
- 顺带证明 `extract_css.py` 的反解思路**是对的**——我用同样的正则在本机 bundle 里独立找到了同构结构。

顺带发现一个很讲究的联动：右边那半屏正在打字机式输出 API 响应，里面写着

```json
"prompt_tokens": 131072,
"prompt_cache_hit_tokens": 131071,
"completion_tokens": 5
```

——而左边的 stats 就显示 `131K tok · 缓存命中 97%`。**两边是同一份数字。**

**asar 格式的一个坑**（记下来省得重踩）：asar 的 header JSON 后面有 **padding**，数据区起点必须对齐到 4 字节 ——

```python
base = (16 + header_size + 3) & ~3      # 正确
base = 16 + header_size                 # 错，差 2 字节
```

用错的那版时，`vendor-BNsW4eBh.css` 提取出来大小一样、但 sha256 完全不同，**差点得出"文件不同"的错误结论**。

## 七、可迁移的几条

1. **"纯函数出帧"适合一切逐帧生成**：调试时任意一帧可单独出图，多进程分段并行零状态，不用做断点续传。
2. **要"忠于某产品的界面"，最省事的路是用它自己的 CSS**：抽出组件样式 + 反解混淆类名，比手画一遍准得多，而且它是真皮肤。
3. **不确定性的动画不要"播放"，要"求值"**：把 `currentTime` 按帧号算出来，重放一百遍都一样。这是可复现渲染的前提。
4. **改造别人的引擎，优先在运行时换函数，而不是改文件**：既不动上游，又能一次性把一整类行为（换图层 / 换标题 / 换波形 / 换歌词）整体替换。代价是要理解"替换的是哪一层"。
5. **版权内容不进仓库、但"可精确重建"**：数据留 sha256 和结构，内容由使用者本机补齐，对不上就拒绝写入——比"删掉相关段落"诚实得多。
6. **替身策略**：当某段素材授权不明时，不动叙事结构，只换**同格式的替身**，让下游一行不用改。这比"删掉这一段"更保全作品。
