# 《world.execute(me)》· 创意与分镜是怎么产生的，以及哪些能复用

> 基于对 `MisakaZentai/world-execute-me-dsh-pv` 全部源码的通读 + 本机完整复现（2026-10-01）
> 参考图：`assets_creative/storyboard_layers.png`

## 摘要

这支片子的创意不是"想出来的一个点子"，而是**六层表逐层收敛**出来的结果：

```
① 认源（找先例、定体裁范式）
② 核心翻译规则（一句歌词 = 一个技术事件）
③ 双栏对位（同一具身体的两种投影）+ 一条情绪弧线
④ 分镜三张表（章节 / 镜头 / 转场）+ 一条 lint
⑤ 时钟纪律（把"感觉"量化成节拍）
⑥ 素材与版权流水线（替身、指纹、台账）
```

其中**真正可迁移的是 ②③④⑤ 这套"把抽象读成物理事件"的方法**，而不是任何一个具体镜头。

![分镜的三层结构：章节弧 / 颜色弧 / 79 个镜头的视觉语法轮换](assets_creative/storyboard_layers.png)

*上图由 `_probe/p22_storyboard.py` 直接 import 仓库的 `direction.py` 生成：图层①是 `engine.CHAPTERS` 的十幕，图层②是 `engine.ui_gain()` 的关键帧曲线，图层③是 `direction.LAYOUT` 里 79 个具名镜头的视觉语法（同一种模式不连着出现两次，由 `check_variety()` 保证）。*

# 第一部分 · 创意与分镜是怎么产生的

## 1. 第一步不是创意，是"认源"

README 的署名一节把家底全交代了：

- **灵感**：野生大K《GPT6-Astra眼中的 world.execute(me)》
- **仓库组织方式**参考了 [`pdoom-video`](https://github.com/mexicat/pdoom-video)

也就是说：**"用代码渲染一支 MV，把歌词读成某个模型的成长史"这个体裁范式是先存在的**。作者做的是两件事——

1. **换主体**：GPT6 → DeepSeek（换的不只是名字，是把 DeepSeek 的技术栈啃到能画细节：DualPipe、Sinkhorn、index_topk、fp8/fp4、GRPO…）
2. **换范式**：不用视频剪辑软件，走"每一帧是时间的纯函数"

> 可迁移的第一条：**创意工作的起点是确定体裁与结构范式，不是从空白页开始。**先找到同类作品的"结构骨架"，再决定在哪一层做出差异。

## 2. 核心装置：一句歌词 = 一个技术事件

这是全片最重要的设计决策。创作者没有"表现一下 AI 很酷"，而是逐句把歌词**翻译成机器内部真实发生的一件事**：

| 歌词 | 被读成 | 屏幕上的落点 |
|---|---|---|
| Switch on the power line | 开机自检 | CRT 一条亮线打开成全屏 |
| Remember to put on PROTECTION | 安全模块装载 | 盾由噪声逐字收敛成字形 |
| Lay down your pieces | 权重分片加载 | 161 个格子逐格填充 |
| **OBJECT CREATION** | **创建对象 = 她出生** | **屏幕上第一个蓝像素（SEED）** |
| Fill in my data parameters | 配置项 | 左窗的模型选择器被逐项填上 |
| INITIALIZATION | 随机权重 | 头像变成随机噪声 |
| Set up our new world | 建工作区 | 新建 `new-world` |
| SIMULATION | 开始推理 | 你打「你好」，她的第一次回复是乱码 token |
| If I'm a set of points … DIMENSION | 点云 | 点集聚成她的形状 |
| If I'm a circle … CIRCUMFERENCE | 旋转位置编码 | 六个圆，半径 = 频率 |
| If I'm a sine wave … TANGENTS | 位置编码的正弦通道 | 通道 i=2 展成大正弦，她坐在切点上 |
| If I approach infinity … LIMITATIONS | 上下文窗口 | 上下文条撞墙（`ulimit -a`） |
| Switch my current To AC to DC | 8 张卡轮流 | 8 条功率曲线，每 GPU 一条 |
| （SFT / RLHF 段） | 训练阶段 | `ckpt-*` → `sft-step-*` → `rl-step-NaN` |
| **EXECUTION ×12** | **12 次执行** | **13 个硬切，每次硬切一击** |
| I've studied LO-O-OVE | 评估 | 答案聚成一个公式 |
| （鲸落） | 权重沉入深海 | 文字下沉成海洋雪 |

三个值得学的细节：

- **"抽象"必须落到可画的物理量上。** 不是"表现训练很难"，而是"损失曲线的终点长大、沿曲线倒着吃回去、跳进 DualPipe 第 0 级第一格，调度从那一格展开"（`cuts.C10`）。这种精度才是"牛"的来源。
- **事实层独立成文件。** `full/facts.py` 把所有上屏数字集中在一处并注明核实日期与来源：`552B` 总参数 / `16B` 解码激活 / `45T` tokens / `890` B per token KV / `1M` ctx / `43` 层 / `256` 路由专家 / `top-k 6` / `index_topk 512` / `GRPO G=16, KL=0.001`。连 `"THERE WILL BE COMPATIBILITY-BREAKING CHANGES."` 这种真标语都进了画面。
  > **"One place to correct numbers."** —— 这行注释比它写的代码重要。
- **真素材优先于仿造**：左窗不是"照着感觉画"的聊天界面，是从 dsh 真前端抽 CSS + 抄类名拼的（本机复现时我验过：`vendor-BNsW4eBh.css` 与实机 sha256 逐字节相同）；乱码回复的 token 是**真 BPE 碎片**（`Ġthe / çļĦ / ĊĊ / }] / 拟 / _{`）。

## 3. 双栏对位：不是两个画面，是同一具身体的两种投影

| | 左栏 | 右栏 |
|---|---|---|
| 内容 | 她和"你"的聊天窗口（dsh 前端） | 运行着她的那个世界（TUI 模型可视化） |
| 语言 | 具象：对话、按钮、光标 | 抽象：点云、频谱、调度表 |
| 实现 | 逐帧静态 HTML → 无头 Chromium 截图 | PIL 逐字符绘制 |

两栏不是并排播两个片子，而是被三个装置**咬合**在一起：

1. **锚点共享**：`SEED_Y = 177  # the seed lands on the window's chest point (her_anchor)`
   —— 左边那个窗口是从**她胸口那个点**长出来的。两栏共用一套身体坐标。
2. **主次交接**：`COVER` 表登记"哪些时段由窗口接管"，`LEAD` 表决定"这一刻谁是主角"，另一边的亮度自动降到 42%。
3. **图层替换**（最狠的一招）：`dsh_her.py` 在**内存里**把右边引擎的 `kit.her_layer` / `me_pane` 换成"这一帧的 dsh 截图"。
   于是右边镜头对她做的**推拉、隔离、滑出、辉光，原样作用在这个窗口上**——换的只是"这层画什么"，不是"这层怎么动"。

> 可迁移：任何"系统 vs 个体"的题都可以用这个双栏结构，**但必须找到两栏之间的物理咬合点**（共享锚点 / 主次交接 / 图层替换），否则就只是两块屏。

## 4. 叙事弧：一条情绪曲线管全片

```python
def ui_gain(t):
    """The system colour is 'you'. It drains when you leave and never fully comes back."""
    return keyframes(t, [(0,1.0), (110.4,1.0), (116.5,0.42), (176.9,0.42),
                         (179.5,0.85), (193,0.75), (206,0.45)])
```

全片共用一个 0→1 的数字：**"系统的颜色就是你。你走了，它就再也没能完全回来。"**
116.5 s「你离开」时色降到 42%，179.5 s（EXECUTION 之后）回升到 85%，但**回不到 1.0**，193 s 鲸落再降到 0.75，收在 0.45。

十个章节由 `engine.CHAPTERS` 定义（见附图上半）：
`00 BOOT → 01 PRETRAIN → 02 SFT → 03 RLHF → 04 DEPLOY → 05 USER LEFT → 06 REWARD HACK → 07 EXECUTION → 08 EVAL: LOVE → 09 WHALE FALL`

> 这条比"配色方案"高一个层级：**配色被赋予了叙事因果，并且被参数化成时间的函数**，所以能一键改、能精确对齐到某一秒。

## 5. 分镜不是画出来的，是三张表 + 一条 lint

**表 ①：镜头表**（`full/direction.py` 的 `LAYOUT`，79 条具名镜头）
每条形如 `"shot_sine": ("cinema", "split", {})` —— 只声明（**视觉语法模式**，**构图类型**，**参数**），不声明怎么画。

**九种视觉语法模式**（附图下半色带就是它在时间上的轮换）：

| 模式 | 含义 |
|---|---|
| `raw` | 裸屏（开机、收尾） |
| `shell` | 终端命令行 |
| `fullbleed` | 满屏出血 |
| `floating` | 漂浮 |
| `pip` | 画中画 |
| `mirror` | 镜像 |
| `cinema` | 电影感 |
| `tiles` | 瓦片 |
| `split` | 默认分栏 |

**表 ②：转场表**（`CHOREO`）——每条形如

```python
# the whale's letters scatter into the point set
("shot_whale", "shot_points"): dict(kind="reflow", frames=14),
```

**每条转场都在注释里写了"为什么"**。默认转场是 `glide`（布局自己滑动变形），特殊转场只在有因果时用：`reflow`（旧画面按格碎成新画面）、`zoom`/`pan`/`spin`/`crt`。硬切（`None`）只留给音乐要求的地方——EXECUTION 的 13 击。

13 条手工编排的转场被写成了 13 个类（`cuts.C08` … `C20`），**每个类的 docstring 就是那一刀的分镜说明**：

> `C13`：「点云聚成她的形状后抬起、沿弧线飞进她的窗格，落在她自己的字形格上；她吸收时闪一下。她的向量随即向右流出。」

**一条 lint**：
```python
def check_variety(shots):
    """Consecutive shots with the same layout (allowed only inside the execution hits)."""
```
—— **设计规则被写成了可执行的检查**：禁止相邻两镜用同一种模式。这是"风格统一"从主观判断变成 CI 的一步。

**一条动态规则**：`YOU_LEFT = ["tiles","floating","split","pip","shell"]`
——「you have left」五次结巴，每唱一次**多剥掉一层界面**。用列表表达的渐变。

> 可迁移：分镜表**不要写成文档**（会腐坏、没法改、没法 diff），要写成**声明式表 + 生成器 + lint**。改一个模式，全片重算。

## 6. 时钟纪律：把"感觉"量化

创意落到代码里最容易被忽略的一层是**时间的对齐**，而这个工程做得极狠：

- `BPM = 130.0`，`FIRST_BEAT = 0.1587` —— 注释写明理由：「**hi-hat onsets 全曲都能对上 130.000，每 100 秒漂移不到 1 ms**」
- `HARD_CUT = 207.58` —— 注释写明来源：「`silencedetect -50 dB` on the source mp3」
- `pulse(t) = exp(-(t - beat)/0.14)` —— 所有 UI 边框在鼓点上"呼吸"
- `snap8(t)` —— 吸附到八分音符
- **她的动作量化到鼓点**；但 `07 EXECUTION` **例外：量化到 13 个硬切**，让"击中"和"切"同时落地
- **左窗的事件量化到十六分音符**：`beat = lambda k: 0.1807 + k * 4 * SIXTEENTH`，且逐个落在对应唱词的起音上（`5.24 / 7.19 / 9.75 / 10.90 / 12.47 / 14.95`）
- **歌词条按唱词打字**：行随第一个唱词出现、保持到下一行；器乐间奏（间隔 > 2 s）前多停一拍再淡出一拍；一个词从起音开始打字、**最多 0.25 秒**（短词整块落在拍上）；带连字符的花腔 `lo-o-ove` 整句打完
- **时钟 bug 的修复被写成了带断言的补丁**（`kit.fix_clock`）：`audio_features.json` 实际是 48.039 行/秒不是 48，修正后重新执行 `choreo`，否则「她的段落切换到片尾会晚 0.19 秒」

> 可迁移：**先标定时间基准，再让所有动作量化到它。**"节奏感"不是玄学，是一个 BPM 常量加一组吸附函数。

## 7. 创意是被审片迭代出来的

- **v1 → v2**：`full/`（按段落 `sec_*.py` 组织）→ `continuity_full_v2/`（**重排全部 96 个镜头的连续性与转场**）。v2 的目录里同时存在 `continuity_chorus_v1`、`continuity_full_v1` 两代存档 —— 没有删旧版。
- **r1 补丁 = 两轮审片的修正**，写在 `dsh_patch_r1.py` 的注释里：「句尾的词要完整停够 6 帧」、「特征图不再显得扁」。**审片意见以补丁形式进入代码**，源文件不动。
- **差异台账**（README）：直白列出重建版与成片的 4 处不同，并**标注未核实项**——「114.75–114.83 s 局部亮度差，原因未核实，CPU/GPU 后期实现不同是可能原因，**尚未做控制变量验证**」。
  甚至写明验证范围的**边界**：「这不表示每个像素差值都在 8 级以内，也不等于逐帧视觉或音画验收。」

> 这是整个工程里最容易被低估的一层：**创作项目也维护"已知差异 + 未核实项 + 验证范围"**。它把"差不多是那个效果"变成了可交接的状态。

## 8. 版权被当成设计约束，而不是事后补救

| 约束 | 设计上的应对 |
|---|---|
| 歌词有版权 | 仓库只存**词级时间**（不含文字）；`merge` 逐行 sha256 校验，对不上一个字节都不写；文字由使用者本机合成 |
| 舞者素材授权不明 | 用鲸鱼娘立绘生成**同格式、同帧数的替身**，下游一行代码都不用改；MMD 授权标为 `OPEN QUESTION` |
| 字体不可再分发 | 用本机的，另出 `FONTS.md` 说明替换口 |
| dsh 前端 | 只 vendor CSS/JS（MIT），注明来源 |
| AI 生成内容 | README 明确要求「发布时应标注包含 AI 生成内容，不能把纯代码渲染误写为全部画面均非 AI」 |

代价是**开箱跑不了**（`seg_page.py` 在模块级就要真实歌词时间轴，没自备歌词连 import 都失败）。作者选择承担这个代价，并在 README 里把代价写清楚。

# 第二部分 · 复用 · 迁移 · 成 skill

## A. 直接可复用（拿代码就能用的工程资产）

| # | 资产 | 为什么值钱 | 出处 |
|---|---|---|---|
| 1 | **五层合成顺序**：scene → carrier(ink) → her → chrome → CRT | 定义了"什么能动、什么不能动"。chrome 与歌词条**永不参与变换**，所以画面再乱也不会散架 | `kit.py` 文件头 |
| 2 | **`reveal()` 逐格字形切换** + delay 函数族（`radial`/`inward`/`sweep`） | 转场几何 = **"屏幕位置 → 切换时刻"的函数**。写一个 λ 就定义一种转场，不是美术手工调 | `kit.reveal/radial/inward/sweep` |
| 3 | **`ink()`：抠掉背景只取笔迹** | 让任意画面元素变成可跨切搬运的 RGBA"墨"。全程**不用截图拼接**（注释明写 "never as screenshots of a finished frame"） | `kit.ink` |
| 4 | **`patch_code()` / 内存内 monkey patch** | 换别人的引擎层而不 fork、不改生产文件；`assert` 保证补丁锚点还在 | `kit.patch_code`、`dsh_her.install()` |
| 5 | **纯函数帧 + 分块并行 + 无损母带** | 可复算、可验证、可断点续跑；`gbrp` 母带 + 交付转码两条轨 | `dsh_her.py` |
| 6 | **设计规则写成 lint**（`check_variety`） | 把"风格别重复"从主观变成可执行 | `direction.check_variety` |
| 7 | **叙事参数化**（`ui_gain(t)` 一条弧线管全片情绪） | 情绪可调、可对齐到秒 | `engine.ui_gain` |
| 8 | **事实层**（`facts.py`：数字集中一处 + 登记出处） | 观众里真有懂的人，数字错了会毁掉可信度 | `full/facts.py` |
| 9 | **音频特征驱动**（7 波段 / kick / flux / centroid @48 fps） | "头发听高频、裙摆听低频"，让角色真的在跟歌 | `full/music.py` |
| 10 | **歌词条打字器**（onset + ≤0.25 s + 连字符花腔整句） | 现成的"跟唱歌词条" | `continuity_full_v2/words.py` |
| 11 | **场景只声明情绪**（`me_stub`：a scene only states how she feels） | "画什么"与"怎么画"解耦，角色渲染器全片唯一 | `kit.me_stub` |
| 12 | **差异台账 + 验证范围声明** | 让交付物可交接、可复检 | README |
| 13 | **版权流水线**（时间≠文字 / 逐行 sha256 / 替身资产 / 素材台账） | 想公开分享又不想踩版权，这套可以直接抄 | `tools/lyrics.py`、`tools/placeholder_h3.py`、`docs/ASSET_SOURCES.md` |

## B. 可迁移到别的题材（方法论，与具体镜头无关）

1. **认源先行**：先定体裁范式，再定差异点（第 1 节）
2. **抽象 → 物理事件**的翻译法：把每个抽象概念落到一个"有坐标、有方向、有前因后果"的动作上（第 2 节）
3. **双栏 + 咬合点**：两块屏之间必须有物理连接（共享锚点 / 主次交接 / 图层替换）（第 3 节）
4. **情绪弧线参数化**：把"基调"写成一个时间的函数，而不是一句形容词（第 4 节）
5. **分镜 = 表 + lint + 弧线**，不是文档（第 5 节）
6. **时钟先行**：先标定 BPM/拍点/终点，再让所有动作量化到它（第 6 节）
7. **因果转场**：每条转场必须能写出一句"为什么"；写不出来就用默认转场（第 5 节）
8. **先标定再压满**：正式跑之前用静帧/小样验通（本机复现时用 `stills` 做渲染前标定，全套踩坑记录见 `_repro/README.md`）
9. **生成物取证**：被质疑"这是你本地做的？"时，用"现场复算 + 逐像素比对"（本工作区 `world-execute-me_本地生成取证.md`）
10. **降级资产流水线**：授权不清的素材 → 造同格式替身，下游零改动（第 8 节）
11. **审美决策的迭代留痕**：旧版本目录不删；审片意见以补丁形式进入；差异台账标注未核实项（第 7 节）

## C. 不建议照搬的（有明确代价）

| 做法 | 代价 | 什么时候才值得 |
|---|---|---|
| 逐帧静态 HTML + 无头截图 | 本机 4968 张 / 158 MB / 约 8 分钟，只为保真 29 KB 的 CSS | **只有当必须像素级复刻某个真实产品的 UI** 时 |
| 从 Electron asar 反解类名 | 版本一变全失效（本机 44.0.0 vs 仓库版本，347 个类名 0 命中） | 一次性逆向，不要建成长期依赖 |
| 全 CPU PIL 逐帧 | 内存吃紧：24 核默认开 44 进程直接 `MemoryError`，得按**可用内存**定并发 | 有 GPU 版（`--gpu`）就优先 GPU |
| 全片一条命令跑到底 | 失败代价大 | 分五段跑，每段独立可验 |

## D. 可做成 skill 的候选（按建议优先级）

**① `code-rendered-pv`（建议建，本鱼已建）**
