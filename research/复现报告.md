## 二、GUI：本机 DSH 的真身

沙箱内 GUI 程序启动被拦，走 WMI 脱离会话拉起 `D:\DSH\DeepSeek Harness.exe`；
`Add-Type` 也被拦，所以窗口操控与截图改走 Python + ctypes（非黑像素占比 **1.000**）。

拿到实机界面后，与 PV 里那个"聊天窗口"做了**文本级对照**——
这些串在实机 bundle 里分别是 `@deepseek-ai/dsh-client-ui-conversation` /
`…-permission-presets` / `…-chat` 的原文，而 PV 把它们逐字抄进了自己的生成脚本：

| 界面串 | 实机位置 | PV 位置 |
|---|---|---|
| `发消息或创建任务，/ 调用指令，@ 文件或对话` | `dsh-client-ui-conversation` | `seg_page.py` / `batch_a1.py` |
| `完全权限` | `dsh-client-ui-permission-presets` | `batch_f.py` |
| `缓存命中` | `dsh-client-ui-chat` | `batch_e.py` / `batch_g.py` |

⇒ **PV 的窗口是照真 UI 复刻的，不是凭空画的。**

## 三、主人様的两份素材：都是"版本"问题，不是"用错"

### 3.1 歌词 → 用了 LRCLIB 的规范版

`tools/lyrics.py merge` 逐行 sha256 校验，主人那份 **98 行里 89 行对不上**（只有 63 个计时行），
merge **一个字节都没写**。改用 LRCLIB 条目 36914646 后：

```
wrote film/ai_mascot_mv_world_execute_20260926/audio/lyrics_synced.lrc: identical to the film's file
wrote film/world_execute_word_timing_20260927/word_timeline.json:         identical to the film's file
```

### 3.2 音频 → 起唱点晚了 124.49 ms，已对齐

判定基准是 B站成片音轨，用**仓库自带的 `chime_g.wav`** 给它定标
（成片把提示音精确放在 207.873 s，实测峰值 **0.9938 @ 207.8730 s** ⇒ 参考轨就在时间零点）。

| 区段 | 主人文件的偏移 | 相关峰 | 次大 |
|---|---|---|---|
| 5 s 起 | **+124.49 ms** | 0.9882 | 0.1528 |
| 150 s 起 | **+124.49 ms** | 0.9808 | 0.1778 |

裁掉 5490 个样本后，残余偏移 **+0.00 ms**。124.49 ms ≈ 24 fps 下的 **3 帧**——
不裁的话，每个词的打出与开口会整体晚 3 帧。

## 六、这次补齐的两颗硬钉子

**① Playwright 的下载器在本沙箱里坏掉。**
`npx playwright install chromium` 报 900 秒超时却在几秒内失败；但同一 URL 用 curl 跑到 **16 MB/s**，
Node 的 `fetch` 也正常 ⇒ **是下载器不是网络**。改为 curl 手动下两个 zip，
按 `browsers.json` 的 revision 解压到 `%LOCALAPPDATA%\ms-playwright\chromium-1243\`，
**并写 `INSTALLATION_COMPLETE` 空标记**（没这个标记等于没装）。

**② 本机没有 ffmpeg/ffprobe。**
剪映自带的那份 `--disable-ffprobe`；`D:\oopz\ffmpeg.exe` 是完整 CLI（含 `libx264rgb`，主母带要用）。
配上 npm 的 `@ffprobe-installer/win32-x64`，装到 `_tools/ffmpeg/bin/`。

## 七、另外三个坑

- **Git Bash 的 `PATH` 里不能塞 `D:/...`** —— 盘符那个冒号会被当分隔符，条目碎成 `D` + `/WorkData/...`，
  `command -v ffmpeg` 永远 MISSING。必须用 `/d/...`。
- **`render` 的并发要按可用内存定，不能按核数** —— 24 核会让默认 `workers=CPU-2=22` 开出 44 个分片进程；
  在"15.6 GB 已被 WorkBuddy/QQ/ChatGPT 占掉 8 GB"的机器上直接 `MemoryError`。取 4 就稳。
- **`pages` 少 120 帧是正常的** —— `COVER` 只覆盖 5.0–125.0 秒，0–5 秒本来就没有窗口。
  `dsh_frame()` 没有 try/except，真缺帧会**直接抛错而不是静默回落**，所以覆盖安全。
